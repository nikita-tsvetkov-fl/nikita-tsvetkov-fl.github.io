Технический SEO-аудит сайта + ТЗ для программиста

Демонстрационный пример формата и глубины. Сайт-образец: интернет-магазин на условном движке (учебный кейс, не реальный клиент). Семантику здесь не собираем — фокус только на технике и готовом задании для разработчика.

Зачем документ. Показывает, как я сдаю технический SEO-аудит: каждая находка → влияние на индексацию/ранжирование → конкретная правка с приоритетом → и, главное, готовое ТЗ для программиста (что именно и в каком файле менять), чтобы разработчик внедрил без переспросов. На реальном проекте все цифры — с краулинга вашего сайта и данных Search Console / Яндекс.Вебмастера.

1. Сводка здоровья сайта

312страниц в индексе 1 040страниц найдено краулером 4,1 сLCP (моб.), порог 2,5 187битых ссылок (404) 0страниц со Schema.org

Главная проблема — раздувание индексации: в индекс попадают фильтры, сортировки и UTM-дубли (728 «мусорных» URL против 312 нужных). Это размывает краулинговый бюджет и каннибализирует ранжирование карточек. Плюс нет микроразметки (потеря расширенных сниппетов) и медленная загрузка на мобильных. Ниже — 14 находок и готовое ТЗ.

3. ТЗ для программиста (фрагмент)

Главная ценность аудита — разработчик берёт и делает, без переспросов. Каждая задача: что, где, как проверить.

ЗадачаЧто сделатьКак проверить
Закрыть параметрические дублиВ <head> страниц фильтров/сортировок выводить <link rel="canonical"> на базовую категорию (без параметров). В robots.txt добавить Clean-param: filter&sort&utm_source&utm_medium (для Яндекса).Вебмастер → «Страницы в поиске»: рост доли товаров, падение дублей; site: по параметру пуст.
Canonical вариаций товараНа карточках с вариациями (цвет/размер через GET) canonical → URL базового товара. Пагинация: canonical на страницу №1 категории.Краул Screaming Frog: 0 «Canonicalised duplicates» по карточкам.
Schema.org ProductВ шаблон карточки добавить JSON-LD Product + Offer (price, priceCurrency, availability), в шапку Organization, в крошки BreadcrumbList. Пример ниже.Rich Results Test / Яндекс «Проверка разметки» — без ошибок; в выдаче цена и наличие.
Core Web Vitals (LCP)Картинки → WebP с фолбэком, loading="lazy" на все ниже первого экрана, width/height для CLS; JS-блокеры — defer; включить Cache-Control: max-age и Gzip/Brotli.PageSpeed Insights моб.: LCP < 2,5 с; CrUX зелёный за 28 дней.
Битые ссылки и редиректыУдалённые товары → 301 на категорию (не 404); схлопнуть цепочки редиректов в один 301; единый хост https + non-www через один 301.Краул: 0 внутренних 404, max 1 редирект-хоп.
Шаблон мета-теговСделать формулы title/description с переменными ({Категория} — купить в {Город} | {Бренд}), запретить пустые description.Краул: 0 дублей title, 0 пустых description.

Пример JSON-LD для карточки товара (готов к вставке)

<script type="application/ld+json">
{
  "@context":"https://schema.org",
  "@type":"Product",
  "name":"{{ product.name }}",
  "image":"{{ product.image_url }}",
  "sku":"{{ product.sku }}",
  "brand":{"@type":"Brand","name":"{{ product.brand }}"},
  "offers":{
    "@type":"Offer",
    "price":"{{ product.price }}",
    "priceCurrency":"RUB",
    "availability":"https://schema.org/{{ 'InStock' if product.in_stock else 'OutOfStock' }}"
  }
}
</script>
