LLM-шлюз — агрегатор нейросетей (аналог OpenRouter / VseLLM)

Единый OpenAI-совместимый API к нескольким провайдерам · ключи · баланс · учёт токенов · биллинг · фолбэк

Демонстрация ядра MVP. Данные на странице — из реального прогона движка (demo_run.py), а не нарисованы. Провайдеры в стенде замоканы; точки подключения боевых вызовов помечены PROD-HOOK.

Как устроен запрос

client Bearer sk-…→ auth по ключу + баланс→ router: model→provider→ провайдер
PROD-HOOK: LiteLLM→ usage→cost, списание→ OpenAI-ответ + ledger

Доступные модели: gpt-4o-mini · gpt-4o · claude-3-5-sonnet · claude-3-5-haiku · gemini-1.5-pro · deepseek-chat. Маршрут и фолбэк-цепочки задаются конфигом — добавить провайдера = строка в карте.

OpenAI-совместимый ответ

Полностью совместим с клиентами OpenAI SDK — меняется только base_url. Поле x_gateway добавляет прозрачность: какая модель реально обслужила, был ли фолбэк, остаток баланса.

POST /v1/chat/completions
Authorization: Bearer sk-…
{ "model": "gpt-4o", "messages": [{"role":"user","content":"…"}] }

→ { "object":"chat.completion", "model":"claude-3-5-sonnet",
     "choices":[{ "message":{"role":"assistant","content":"…"} }],
     "usage":{ "prompt_tokens":…, "completion_tokens":…, "cost_usd":… },
     "x_gateway":{ "requested_model":"gpt-4o", "served_model":"claude-3-5-sonnet",
                   "fallback_used":true, "balance_after":… } }

Что в боевом MVP (этапами)

Этап 1 — шлюз + маршрутизация + выпуск API-ключей (это ядро на странице).
Этап 2 — личный кабинет, история запросов, учёт токенов и стоимости по моделям.
Этап 3 — биллинг: приём рублёвой оплаты (ЮKassa/CloudPayments webhook → пополнение баланса), PostgreSQL, Docker-compose, aiogram-бот уведомлений.
Маршрутизацию и фолбэк в проде закрывает LiteLLM (proxy-режим) — даёт OpenAI-совместимый /v1 и подключение OpenAI/Anthropic/Gemini/DeepSeek из коробки, поверх — наш слой ключей/баланса/биллинга.

Деплой — на инфраструктуре заказчика (его VPS, его ключи провайдеров).
