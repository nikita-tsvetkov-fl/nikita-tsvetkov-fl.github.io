ERC-4626 Vault NAV Reconciliation

Read-only on-chain audit of a tokenized vault's net asset value · raw JSON-RPC · zero trust in a single source

A NAV automation / reconciliation primitive an RWA or DeFi product needs: pull live vault state, compute NAV-per-share, and cross-check it against the vault's own convertToAssets() preview so any pricing/accounting drift is flagged before it reaches investors or downstream reporting. The numbers below are from real mainnet runs, not mocked.

How a check runs

vault address→ raw eth_call
(no web3.py, any RPC)→ read state
totalAssets / totalSupply→ NAV/share two ways→ reconcile vs
convertToAssets()→ OK / MISMATCH + json

Dependency-light — httpx only, no node, no signing keys. Output is a human report or --json for a monitoring/alerting pipeline.

Where it fits in production

  • Schedule per block/interval, emit --json to a time-series store.
  • Batch multiple vaults via multicall for efficiency.
  • Wire MISMATCH to alerting (Telegram / PagerDuty) and a reconciliation dashboard for share classes / pools.
  • Extend to ERC-7540 async request lifecycle (pending deposit / redeem queues).

Read-only by design — it never holds keys or sends transactions. This is one of several Web3 building blocks I build to order (contract audit-assist, tests, NAV/oracle feeds, MetaMask/wagmi front-ends).
